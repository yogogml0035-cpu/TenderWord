## Codebase Patterns

- Generate-only request fields currently follow `generation_style` and `style_writeback_mode`: backend model -> `DocumentService._build_initial_state()` -> graph state -> frontend form/converter/draft tests.
- Generate-only fields that must always reach `/api/generate` can be optional in form draft data, but converters should normalize missing values to explicit API defaults.
- Standard generate graph centralizes shared flow in `StandardTenderWorkflowGraph`; type graphs should not copy the generation mode split.
- The current LLM content card is driven by `llm` events for `generate_polished_text`; agent audit/revision display must use a new `agent_step` event and keep `done` / `error` as terminal events.
- Graph difference coverage should target `xjcg`, `gngk_hw_zc`, `gngk_hw_cz`, `gngk_fw_zc`, and `gjgk`; inherited `gngk_fw_cz` only needs smoke.
- Workflow branch regression tests can subclass `StandardTenderWorkflowGraph` with fake nodes and assert `NODE_HOST_AGENT_GENERATE` is not called while `generation_mode` remains `workflow`.
- The old generate content card contract is anchored by `TASK_KIND_TO_LLM_NODE["generate"] == "generate_polished_text"` plus `_LLMSnapshotRelay` emitting `llm` events with `content_mode: "snapshot"`.
- DeepAgents `CompiledSubAgent` is a `TypedDict`; custom subagents should be dicts with `name`、`description`、`runnable`，and the compiled runnable state must include `messages`.
- DeepAgents model construction should reuse `MODEL_CONFIGS` and `settings.get_llm_config()`; pass common ChatOpenAI params like `temperature` and `max_tokens` explicitly, while provider-specific `extra_body` stays from `MODEL_CONFIGS`.
- Host agent runtime tests should drive a deterministic phase sequence (`generate` -> `verify` -> `revise`) through the fake runner payloads; this locks workflow order without invoking real DeepAgents or LLMs.
- LangGraph conditional edges cannot be attached directly to a list-based join; add a lightweight gate node after the join and have it return `{}` so it does not concurrently rewrite existing state keys.
- 新增 SSE 事件必须双侧补契约：后端 `backend/models/sse.py` / `SSEManager` 负责模型、缓冲与重放，前端 `frontend/types/api.ts` 必须同步事件 union 和 payload interface，并用独立类型测试锁定。
- 浏览器层 SSE named event 必须在 `frontend/lib/sse.ts` 的 `createSSEConnection()` 中显式 `addEventListener`；只在 `useChatSSE` 单测里 mock `onMessage` 不能覆盖真实 EventSource 传输。
- 智能体过程卡不要复用旧 `task-content` 单卡；使用独立 `agent-step` messageKind 持久化 draft/audit/revision，避免 `ChatPanel` 的运行时 `aiText` 合并覆盖历史过程卡。
- 逐类型 graph agent 分支验证可复用真实 graph 类，通过 monkeypatch 类级 `NODE_*` callable 替换 Word/LLM 节点，并用 `set_generation_agent_runner()` 注入 fake runner；这样能验证真实 mode gate 和后续 `update_word` 接收的 `polished_text`。
- 逐类型 graph 测试不要把未声明在 `TenderGraphStateBase` / 专属 state 中的字段当作跨节点契约；优先断言已声明 state、真实节点绑定、调用顺序和 update 节点核心入参。
- `gjgk` graph 的 `replace_content` 是 `get_post_update_steps()` 中的 post-update hook；验证国际公开链路时应锁定 `gjgk_update_word -> replace_content` 顺序，而不是只断言 update 节点。
- `gngk_fw_cz` 当前是 `GngkHwZcTenderGraph` 的继承复用链路；smoke 测试应断言继承来的 common delete/update 与 `gngk_hw_zc_get_replacements`，再用 fake runner 验证 mode gate 未断。
