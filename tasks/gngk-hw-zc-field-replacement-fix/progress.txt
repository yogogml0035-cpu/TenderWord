## Codebase Patterns

- `gngk_hw_zc_get_replacements` is the current graph wrapper for domestic public goods self-funded replacement extraction.
- `run_get_replacements` builds `placeholder_mapping` and `replacements` from extractor specs and replacement field specs; this task should reuse that mechanism.
- Core validation can use mocked document content and should not require a real external tender lookup API.
- Tender data fields that feed generation should be synchronized across `backend/models/tender.py`, `backend/states/base_state.py`, `backend/services/document_service.py` initial/rewrite state keys, `backend/util/common_util/fetch_tender_data.py`, `backend/api/tender.py`, and `frontend/types/api.ts`.
- Public tender buyer extraction should support both `采购人` and `招标人` labels, while budget extraction should treat only explicit `预算金额` lines as the `investment` source; `最高限价` remains a downstream global replacement effect, not a source field.
- Public tender contact extraction is shared across `gngk`/`gjgk`; `project_zbr_xbr` should support `项目联系人`/`联系人` and stop before contact-method labels such as `电话`/`电 话`/`传真`/`邮箱`/`电子邮箱`.
- `ReplacementFieldSpec` supports `new_value_formatter` for field-level new-value normalization before replacement pair generation; use it for amount-like fields instead of pre-mutating generation state.
