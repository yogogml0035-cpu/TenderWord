## Codebase Patterns
- 新的 NDJSON 流式接口复用 `backend.services.chat_stream_service.to_ndjson_line`，并由 `StreamingResponse` 直接返回异步迭代器。
- 后端流式路由测试优先直接调用 API 函数并消费 `response.body_iterator`，不必额外起 `TestClient`。
- 前端流式 API client 统一在 `frontend/lib/api.ts` 通过 `streamNdjson + parse<Event>` 组合实现，具体事件合同集中定义在 `frontend/types/api.ts`。
- fake agent run 产出的占位 `task_accepted` 只能复用任务卡 UI，不能继续挂在 `activeTaskIds/currentTaskId/taskSummaries` 上，否则 `heartbeat/getTaskStatus` 会把占位任务误判成后端重启。
- 显式 agent skill 选择应该放在 `conversationDraft.selected_skills`，发送时写入 `streamAgentRun.selected_skills`，并在消息发出后立即清空，避免把一次性 capability 泄漏到下一条消息。
- 即使当前 draft 已进入 `edit` 模式，只要用户显式选中了 `/edit` 或 `$edit`，`ChatPanel` 也应优先走 agent run，而不是回退到旧的直连 `createEditTask` 路径。
- 用户消息里的 capability 展示和复制回放应基于 `metadata.chatKind` 派生；正文始终显示去前缀后的内容，复制时再恢复 `$skill` 前缀。
- agent run 思考过程卡应作为独立 AI 消息保存到 `metadata.agentThinking`，在 `task_accepted` 前消费 `run_started/thinking_stage/tool_call` 增量更新，`task_accepted/needs_input/done/error` 只负责把卡片收敛到终态并把后续展示交给任务卡或助手回复。
- DeepAgents task-context assistant 不要直接把 `backend/skills` 或项目根挂给 agent；应先把允许的 skill 目录镜像到隔离 runtime，再用 `CompositeBackend` 分开 `/skills/`、`/scratch/`、`/workspace/` 三个虚拟根。
