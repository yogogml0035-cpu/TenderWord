## Codebase Patterns

- `backend/prompts/comment_prompt.py` 是当前批注生成 prompt 唯一真源；新增 retrieval-aware 入口必须复用它。
- `generate_comments` 负责 workflow 批注生成和 prompt/raw/repaired/new_comments 日志；bad case 增强应在 LLM 调用前完成。
- `comment_agent` 只有在 `allow_comment_generation=True && initial_comments=[]` 时自主生成批注；已有候选时是锚点修复模式，不注入 bad case。
- `backend/retrieval/` 已是批注 bad case 检索正式增强入口；文档边界应保持只接入 `generate_comments`、自主生成模式 `comment_agent` 和 `comment_supplement`，不进入 rewrite 或 `comment_generation_mode=off`。
- Ralph stories 已收窄为 15 个可独立验证切片，按 loader、目录、缓存、切分、BM25、hybrid、context、日志、prompt、节点、脚本、文档、回归的依赖顺序执行。
- `backend/retrieval/bad_case_loader.py` 暴露正式 bad case 默认目录和主文件入口；v2 `---BEGIN_BAD_CASE---` 解析与旧格式解析需要保持兼容。
- `load_bad_case_directory()` 是目录级 bad case runtime 入口；它按文件名扫描 `*.md`，坏文件只进入 warning/failure payload，不应阻断有效文件加载。
- `frontend/package.json` 的开发验证入口当前固定为 `next dev --webpack -p 8502`；默认 Turbopack 在本仓库的 Tailwind 4/lightningcss 组合下会在 Linux/WSL 里卡在 native module 解析。
- `load_bad_case_runtime_index()` 是 bad case chunks + BM25Index 的进程内缓存入口；后续 clause split、BM25-only 和 hybrid runtime 应复用它，不要直接重复构建索引。
- `split_polished_text_into_clauses()` 是正式 clause_only 切分入口；只识别 `第N包：`、中文数字章节和数字顿号条款，不能在首版扩展到 `1.1`、`（一）` 或表格单元格。
- `retrieve_bad_case_hits_bm25_only()` 是正式 BM25-only 入口；它返回 `BadCaseRetrievalResult`，按 clause 保留 `pre_filter_hits` 和 `filtered_hits`，并统一标记 `retrieval_mode=bm25_only`。
- `retrieve_bad_case_hits()` 是正式 hybrid-first 入口；它只查询 Qdrant，不 upsert、不 recreate，任一向量环节异常都会带 warning 回退到 BM25-only。
- prompt 注入前先用 `select_injected_bad_case_hits()` 做 `case_id` 级去重和按 `(-score, case_id)` 稳定排序，再由 `build_bad_case_prompt_context()` 投影到 5 个可注入字段，避免把审计字段泄漏给模型。
- `BadCaseRetrievalResult.to_log_payload()` 是 retrieval JSON payload 真源；后续节点只应序列化它，不要在 `generate_comments` 或 `comment_agent` 中重组检索细节。
- `render_comment_prompt_with_bad_case_context()` 是 retrieval-aware 批注 prompt 渲染入口；空 context 必须与 `render_comment_prompt()` 输出兼容，非空 context 只消费 5 字段 prompt context。
- `generate_comments` 的 bad case 增强集中在 `_build_bad_case_context_for_comments()`；无 context 时仍走 `render_comment_prompt()`，有 context 才走 `render_comment_prompt_with_bad_case_context()`，`comments_prompt_file` 保存最终实际发送 prompt。
- `generate_comments` 的 retrieval JSON 只写入 prompt log 目录下的 `*_comments_bad_case_retrieval_*.json`；节点仅补充完整 `polished_text` 并序列化 runtime payload，不把日志路径写回 state 或前端可见字段。
- `comment_agent` 自主生成模式的 bad case 检索必须放在 Word 打开且锚点范围解析完成之后；prompt/retrieval 证据写入 `comment_agent_audit` 目录，不回传 state、SSE 或下载卡。
- `backend/scripts/test_comment_hybrid_retrieval.py` 只是正式 runtime 的诊断壳；默认读取 `backend/retrieval/bad_cases`，不再保留独立 v2 解析、条款切分、Qdrant upsert 或 collection recreate 逻辑。
