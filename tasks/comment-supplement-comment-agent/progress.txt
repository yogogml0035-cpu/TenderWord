- SSE `done` 新增结构字段时，需要同步后端模型 `backend/models/sse.py`、发送入口 `backend/core/sse_manager.py`、前端 `frontend/types/api.ts` 与类型契约测试。
- Windows/WSL 共用工作区时，前端浏览器验证前要确认 Linux 原生 optional 依赖已安装；若 `lightningcss` 或 `@tailwindcss/oxide` 只存在 win32 包，在 `frontend/` 运行 `npm install --include=optional` 后重启 dev server。
- 批注写回 summary/warning 规则统一走 `backend/nodes/common_word_nodes/comment_writeback.py::build_comment_writeback_summary_payload`；update_word 节点只在 `generated > 0 && failed > 0` 时用 `progress_log.warning()`，不要重新加入 0 写入硬失败。
- `DocumentService._build_rewrite_state_snapshot()` 可以保存后端内部批注依据长数组和 `generation_mode`；`_build_task_result_payload()`、SSE `done` 和前端 `chat-storage` 只能保留白名单摘要字段，不能泄露 `comment_plan_detail`、`strikethrough_plan`、`non_black_font_plan`。
- 新增 Prompt Layer builder 时同步补 `backend/prompts/types.py` 输入 dataclass、`backend/prompts/__init__.py` 导出和 `backend/tests/prompts/test_*.py` 契约测试；Prompt Layer 仍只做纯渲染，不接日志、LLM 或 Word 副作用。
- `comment_agent` 采用“纯确定性函数 + LangChain StructuredTool factory”的分层：校验只读取 `polished_text`，Word 写入工具必须重新校验并限制在 `bound_start/bound_end` 内，不复用全文兜底写回。
- agent generate 批注链路由 `StandardTenderWorkflowGraph` 统一编排：`comments_branch_done` 设置 `suppress_ai_comment_writeback=True`，各类型 `update_word` 只写正文/样式/保存，随后进入公共 `comment_agent` 节点；不要在类型 graph 里复制该分流。
- `comment_supplement` 后端闭环固定走 `POST /api/comment-supplement -> DocumentService.create_comment_supplement_task -> CommentSupplementGraph`；创建任务前必须校验传入 `source_file` 等于 latest `rewrite_state.prepared_doc_path` 且文件存在。
- 补充批注成功后通过 `ConversationService.append_comment_supplement_success()` 追加 assistant rewrite_state，使 latest `prepared_doc_path` 指向补充批注副本，后续 rewrite/edit 继续读取 latest rewrite_state。
- 前端任务完成入口有两条：`useChatSSE` 的 SSE `done` 与 task status fallback、`FormPanel.syncTaskTerminalState()`；新增 result 摘要字段时两条路径都要传给 `chatStore.completeTask()`。
- 下载卡的用户动作以 `message.metadata.taskKind` 判定任务来源；`comment_supplement` 从 generate 下载卡进入 `ChatPanel -> createCommentSupplementTask -> startTask`，不要在卡片组件内直接访问 store 或裸 `fetch`。
- `comment_agent` 的 `agent_step` 事件是一组同 node/round 的 AIMessage 内容片段，前端应按顺序追加到同一张卡；最终 `is_complete=true` 且 `content` 为空时只收尾，不清空已追加内容。
- Next dev 会自动把 `.next/dev/types/**/*.ts` 加回主 `tsconfig.json`；前端稳定类型检查走 `frontend/tsconfig.typecheck.json`，避免 dev 生成缓存里的 validator 语法问题影响 `npm run type-check`。
- 当前根路径 `/` 直接重定向到 `/tender` 工作台；首页类 E2E 应断言 tender workspace 的真实入口元素，不要继续依赖历史 landing page 的 `进入使用` 链接或 `main` 内容。
- Playwright E2E 若写 requirement 证据，artifact root 必须指向当前任务目录；不要把新截图或 console 日志写入旧 Ralph 任务目录。
